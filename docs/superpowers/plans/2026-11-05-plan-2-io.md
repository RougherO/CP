# Plan 2 — I/O — Implementation Plan

> **For agentic workers:** executed natively (superpowers:executing-plans), one module per turn, pausing after each.

**Goal:** `cp::in`, `cp::out`, `cp::err` and the free `read`/`write`/`writeln`/`getline`, fast enough that I/O is never the bottleneck, correct on files, pipes and interactive judges, at C++17/20/23/26.

**Module restructure (owner, 2026-11-06):** public names now live in module namespaces (`cp::io::read`, `cp::io::in`, …); see spec §6.3. Names in this plan written `cp::x` mean the module-qualified name.

**Architecture:** Three layers. `sys/` owns the OS calls (one input source, one output sink). `io/parse.hpp` and `io/format.hpp` are pure functions over `char` buffers, with no OS and no stream state, so they are tested exhaustively. `io/reader.hpp`/`writer.hpp` hold the buffer, the options and the dispatch (`codec<T>` plus the ADL hooks); `io/io.hpp` defines the three streams and the free functions.

**Spec:** `docs/superpowers/specs/2026-11-04-cp-library-design.md` §8 (all of it), §3, §7. §10 reporting comes in Plan 3; until then errors go through `cp::detail::precondition`.

**Owner rules carried from Plan 1:** modules first; tests only for risky behaviour; most modern std API with the C++17 fallback in `#else`; no helper duplicated across modules (reuse `cp::wide`, `compat/*`); benchmark numbers for performance-sensitive modules; commit only when asked.

## Global Constraints

- All Plan 1 constraints (language levels, compilers, 64-bit, `config.hpp` the only macro file, `// cp:since` tags, self-contained headers, `inline` non-templates).
- OS headers (`<unistd.h>`, `<sys/mman.h>`, `<io.h>`, `<windows.h>`) only under `include/cp/sys/`.
- `fread` is never used for input. Output newlines are always `\n`.
- Reader guarantees ≥ 64 readable bytes after the cursor, `'\0'`-terminated at end of input; buffer size is a template parameter (default 64 KiB). Writer flushes when < 64 bytes free.
- No cp free function shares a name and a viable call shape with a std function; formatted output is `cp::out.print`/`println` (members).
- No `operator<<`/`operator>>` in cp I/O; one extension point: ADL `cp_read(cp::reader&, T&)` / `cp_write(cp::writer&, T const&)`.
- Release builds: bad input gives an unspecified value, never a crash or hang.

## Review Focus

1. Interactive judge: the reader must flush `cp::out` before a refill that can block, and must return after a partial `read(2)`. Test with a pipe fed one line at a time by a child process.
2. Input file whose size is an exact multiple of the page size (mmap SIGBUS on the padding). Test with a 4096-byte file.
3. A token straddling the refill boundary (number or string split across two `read` calls). Test with a reader buffer of 128 bytes over a pipe.
4. Extremes: `INT64_MIN`, `UINT64_MAX`, `-0`, `+5`, 19/20-digit numbers, `i128` min/max, leading zeros, `\r\n` line ends. Round-trip tests.
5. No trailing newline at EOF, empty input, and `while (cp::read(x))` stopping exactly once.

### Task 1: `sys/input_source.hpp`, `sys/output_sink.hpp`

- `cp::detail::input_source`: `fd`-based. `open_stdin()` picks: POSIX regular file → `mmap` (size % page == 0 → read whole file into a heap buffer instead); pipe/TTY → chunked `read(2)`; Windows → same choices with Win32 calls on `_get_osfhandle(fd)`: `GetFileType`/`GetFileSizeEx` → `CreateFileMappingW` + `MapViewOfFile` (or slurp), else chunked `ReadFile`; output via `WriteFile`. `config.hpp` sets `NOMINMAX`/`WIN32_LEAN_AND_MEAN` on Windows. Interface: `auto read_some(char* dst, std::size_t max) -> std::size_t` (0 = EOF, never waits for a full buffer), `bool may_block() const` (false for mmap/slurp), and for mmap/slurp a `span<char const>` of the whole input so the reader can skip copying.
- `cp::detail::output_sink`: `write_all(char const*, std::size_t)` looping over `write(2)`/`_write`, retrying on `EINTR`.
- Tests (POSIX): pipe with partial writes from a forked child returns per chunk; 4096-byte regular file and a 4097-byte one give identical bytes; empty file.

### Task 2: `io/parse.hpp`, `io/format.hpp`

- Parse (pointer in, pointer out, no bounds checks, relies on the 64-byte invariant): `parse_int<T>(char const*& p, T& out) -> bool`, all integer types including `cp::i128/u128`; branch-free sign, then a plain digit loop in u64 (SWAR measured slower, see ledger); > 19 digits re-read with `cp::mul_wide`/`add_wide` checks. Overflow always detected (free up to 19 digits); the reader reports it under `CP_CHECKS`. Base option (`2..36`) on the checked path. Shared tables in `io/digits.hpp`.
- Float parse: `std::from_chars` when `__cpp_lib_to_chars >= 201611L` covers floating point, else `strtod` on the token. Token is copied to a small stack buffer only on the fallback path.
- Format: `format_int<T>(char* p, T v) -> char*` with the `"00".."99"` table, fixed-width options (`base`, `width`, `fill`, `show_sign`); `format_float(char*, F, fmt, precision) -> char*` via `std::to_chars`, else `snprintf`. Max output length per type as `constexpr` (so the writer reserves without measuring).
- Ruling recorded: spec §8.4 names `mul_overflow`/`add_overflow`; those became `cp::mul_wide`/`add_wide` in Plan 1.
- Tests: every length 1..20 for u64 and i64, boundary values from Review Focus 4, random round-trip 10⁶ values per width, i128 extremes; float round-trip at precision 17 and fixed 9.
- Bench (part of `bench_io.cpp`): parse/format throughput on 10⁷ in-memory integers vs `std::from_chars`/`to_chars`.

### Task 3: `io/options.hpp`, `io/codec.hpp`, `io/reader.hpp`, `io/writer.hpp`

- Options exactly as spec §8.8 table: `read_options<T>`/`write_options<T>` aliases to per-category structs; `input_options`, `output_options` aggregates with chainable `constexpr` setters for C++17; `options()` get and `options(new) -> old` set.
- `cp::reader(int fd, std::size_t capacity = 65536, writer* tie = nullptr)` (capacity is a constructor argument, not a template parameter, so `cp_read(cp::reader&, T&)` fits every reader): lazy open at first read; parse each token against the `'\0'` sentinel and refill + reparse only when the token runs into the end of the buffered bytes (no 64-byte look-ahead, which existed for SWAR); tie flushed before a refill only when `may_block()`; sticky failure, `eof()`, `explicit operator bool`, `clear()`; `getline` drops `\r`; bad tokens/overflow abort with the input line under `CP_CHECKS`, end of input never does.
- `cp::writer(int fd, std::size_t capacity = 65536, bool write_through = false)`: reserve-then-format, `flush()`, flush in destructor, public `put(char)`/`put(string_view)` for hooks; width/fill/sign padding here.
- Dispatch order (spec §8.10): ADL hook → bool/char/strings → arithmetic → ranges (incl. `vector<bool>`, nested ranges one row per line) → tuple-like → aggregates (`io/aggregate.hpp`: PFR field counting up to 32 fields; reflection branch under `__cpp_impl_reflection`, `// cp:since c++26`, tested with GCC 16 `-freflection`). No match → `static_assert` naming the type. Reading into `const` or a temporary → `static_assert`.
- Tests: reader with `BufSize = 128` over a pipe for Review Focus 3; strings longer than the buffer; `\r\n`; `read(char&)` skips whitespace; `vector<bool>`; ADL hook; aggregate with nested `std::array`/`pair`; EOF conversion for Review Focus 5.

### Task 4: `io/io.hpp` + `aliases.hpp`

- `inline basic_reader<> in;` `inline basic_writer<> out;` `inline basic_writer<4096, true> err;` with `in` tied to `out`. Free `read(args&...)` returning `reader&`, `read<T...>()` (one T → T, several → `std::tuple`), `write`, `writeln`, `getline(reader&, std::string&)`.
- No RAII options type (owner, 2026-11-06): `options(new)` returns the old options; restoring is one call.
- `aliases.hpp` per spec §11 (`i8…u64`, `isize`, `usize`, `_i64 _u64 _iz _uz`; `_uz` tagged `cp:since c++23`). Not in `all.hpp`.
- Tests: both-namespaces TU gains every new name; a forked child running an interactive exchange (Review Focus 1).

### Task 5: `io/format_string.hpp` (`cp::out.print`/`println`) — DROPPED for now (owner, 2026-11-06)

- Spec subset of §8.9: `{}`, `{n}`, fill/align, sign, `0`, width, precision, types `d x X b o f e g c s`; `std::format` semantics, no stream options consulted; user types `{}` only.
- C++20+: `cp::format_string<Args...>` with a `consteval` constructor that stores a segment table; bad specs are compile errors. C++17: runtime parse, errors via precondition.
- Tests: output matches `std::format` (when `__cpp_lib_format`) on a fixed table of specs × values; compile-fail cases checked by a `requires`-based probe under C++20.

### Task 6: `bench/bench_io.cpp`, new `main.cpp`, `.vscode`

- `xmake iobench`: whole programs (`bench/io/io_*.cpp`) reading and writing 10⁷ 64-bit integers, file and pipe, best of 5, outputs cross-checked: `cp` vs `scanf`/`printf` and unsynced `cin`/`cout`. The old template is not a baseline (owner, 2026-11-06: redundant).
- `main.cpp` becomes the thin template (no legacy copy kept: owner, 2026-11-06); xmake `main` target keeps building `main.cpp`.
- `.vscode` tasks/launch updated for the new tests and bench.
